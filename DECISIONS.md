# Implementation decisions

These are decisions taken while turning the proposal into a working system, with the reason for
each. The proposal's design is kept. Where we deviate, the change is a *configurable default*, chosen
so the system runs at $0 on an 8 GB laptop. The proposal's original choice remains one setting away.

| # | Decision | Reason | Switch back to the proposal's choice |
|---|---|---|---|
| D1 | The default LLM provider is **`offline`**: a deterministic, rule-based path in every agent (template queries per legal element, extractive IRAC drafting from verified passages). | $0 budget during development. A deterministic mode also makes the Citation Firewall and the approval gates fully testable. | `STARE_LLM_PROVIDER=anthropic` (Claude, `STARE_LLM_MODEL`/`STARE_LLM_FAST_MODEL`) or `openai_compat` with a free local Ollama server (`STARE_LLM_BASE_URL=http://localhost:11434/v1`). |
| D2 | The default database is **SQLite**. The schema is identical on PostgreSQL 16 + pgvector (vector column type and `<=>` search branch). | No Docker or Postgres on the laptop. | `STARE_DATABASE_URL=postgresql+psycopg://…` and `docker compose up db` (see `docker-compose.yml`). |
| D3 | The original default dense embedder was **LSA** (now the fallback, see D16) (TF-IDF + truncated SVD, 256 dims), fitted on the corpus. | No neural model download or CPU-heavy embedding on the laptop. | `STARE_EMBEDDER=lsa`, then `stare index build`. |
| D4 | The default reranker is **lexical** (feature-based). | A cross-encoder is a neural model (heavy). | `STARE_RERANKER=cross_encoder`. |
| D5 | The corpus is **5,120 real federal employment opinions**: a curated seed of 151 leading cases (`data/seed/`) plus 4,969 opinions found by following their citations two steps out in CAP (`data/expansion/`, `stare ingest expand`), cached as gzip JSON so a fresh clone builds offline, plus the statute and regulation text. | The CourtListener and CAP bulk files are many GB and too large for an 8 GB laptop; citation snowballing keeps only cases the leading authorities actually rely on. | `stare ingest courtlistener-bulk DIR` / `stare ingest cap-bulk DIR` (importers implemented and tested on fixtures), or `stare ingest expand --hops 3`. |
| D6 | The CourtListener API is the Gate 2/Gate 4 fallback **only**. It is anonymous unless `STARE_COURTLISTENER_TOKEN` is set (free account), and rate limited and cached. When it is unavailable, citations become `unresolved`, which is never exportable (NFR-06). | The free API has limits; the local index answers first. | Set a free token to enable the citation-lookup endpoint. |
| D6b | Gate 2 also consults the **Caselaw Access Project volume listings** on static.case.law (free, cached), which say exactly which case begins on each page of every published volume up to CAP's coverage end. A citation to a covered volume where no case begins on that page is blocked. A miss in CourtListener's *anonymous* search is treated as unresolved, not nonexistent, because that index can omit real opinions. Only the authenticated citation-lookup API proves non-existence. | No account is needed and there are no rate limits. It avoids falsely blocking real recent cases. | `STARE_CAP_LOOKUP_ENABLED=false`. Set `STARE_COURTLISTENER_TOKEN` for authoritative lookups of WL, neutral and post-2019 cites. |
| D7 | Gate 2 checks the **case name** as well as volume/reporter/page. | Several Mata fabrications point at real reporter pages that belong to other cases. Existence of a page is not existence of the cited case. | — |
| D8 | PII redaction uses **Presidio with spaCy `en_core_web_sm`** when installed, plus a regex layer. When Presidio is absent, the regex engine is used alone. A final guard refuses to send any prompt that still contains SSNs, emails or phone numbers. | The large spaCy model is 560 MB. The small one is enough with the regex layer, and the guard enforces NFR-03 for any provider. | `pip install -e '.[presidio]'` and `python -m spacy download en_core_web_lg`. |
| D9 | The raw uploaded file is **deleted after extraction** by default. Only redacted text is stored. | NFR-03: no raw client text in storage or logs. | `STARE_KEEP_RAW_UPLOADS=true`. |
| D10 | The plan gate and the memo gate are **LangGraph `interrupt()`s** with a SQLite checkpointer. A run survives a server restart. | Section 5.3.4: the graph cannot continue until an approval is recorded. | PostgresSaver when on PostgreSQL. |
| D11 | The general-purpose LLM baseline (Table 29) uses a **free** model (opencode `beam-free`) to answer the 100 gold questions without retrieval; `stare eval baseline --answers FILE` scores any model's answers with the same Firewall. Citations the free CourtListener API could not check because of its rate limit are reported as unresolved and separately. | $0 budget. | `stare eval baseline` with `STARE_LLM_PROVIDER=anthropic` (paid) or a local model. |
| D12 | With the larger corpus, the Research Agent searches each plan item three ways: the whole corpus, the Supreme Court only, and the filing court's own circuit only; it then promotes **co-cited** opinions (cited by at least 3 of the item's top 20 case authorities, relevance 0.5 + their share) with their own best passages. | Hundreds of lower-court opinions quote the leading cases nearly word for word, so text search alone ranked the leading case below them (recall@10 fell from 0.775 to 0.475 on 20 questions before this change). Following citations is what a lawyer does. | `COCITE_TOP`, `COCITE_MIN`, `COCITE_MAX` in `stare/agents/research.py`. |
| D13 | **STARE-Gen**, a model trained in this project, writes one rule sentence per verified case authority in the memo. It is SmolLM2-135M-Instruct fine-tuned on 3,838 pairs mined from the corpus itself: a passage of a cited opinion and the sentence in which a later court stated the rule it took from it (`stare gen data`, `stare gen train`). | A small model runs on the laptop at no cost, and real judicial writing is the best available example of stating a rule from a source. Its output is never trusted on its own: the citation and the verified quotation are attached by code, a grounding check rejects any sentence that cites anything or whose content words are not in the passage, and the Firewall still checks the memo. Off by default: on 200 held-out passages it doubled the base model's grounded output (29% against 14%) but still misstated some rules, so it is an opt-in, labelled "Summary (STARE-Gen)" and always followed by the verified quotation. | `STARE_MEMO_WRITER=stare_gen` turns it on. |
| D14 | Every memo gets a **confidence score**: verification 35%, binding authority 25%, coverage of the plan items 25%, retrieval relevance 15%; High at 0.80 or more, Medium 0.60, Low 0.40. | The attorney sees at a glance how well the memo is supported; it is not a prediction of the outcome. | Weights in `stare/confidence.py`. |
| D15 | **Query-type routing**: a question that names a case, a reporter citation or a statute section gets an exact-match lookup, and what it names is ranked first. | Text search can bury the very case the attorney asked about: on 40 questions naming the 40 most-cited opinions, hybrid search alone put the named case in its first 10 opinions 5 times, routing found it 40 times (`python -m stare.eval.routing_bench`, docs/evaluation/routing_named_authorities.json). | `stare/agents/routing.py`. |
| D16 | The default dense embedder is **bge-small** (BAAI/bge-small-en-v1.5, 384 dimensions) through sentence-transformers, on the Apple GPU (MPS) or CUDA when present; LSA remains the fallback when the `neural` extra is not installed. | Neural embeddings retrieve better than LSA (cloud run: recall@10 0.885 against 0.860). On the 8 GB laptop the ONNX (fastembed) CPU path needed about 3 hours for the 103,977 chunks; the GPU path about half an hour. | `STARE_EMBEDDER=fastembed` (CPU) or `lsa`. |
